# Deployment Guide

## Overview

| Layer | Platform | Notes |
|-------|----------|-------|
| React frontend | **Vercel** | Free tier; auto-deploys from GitHub |
| FastAPI backend | **Render** | Docker web service; auto-deploys from GitHub |
| Metadata DB | **Render Postgres** | PostGIS extension required (see below) |
| Features DB | **Render Postgres** | PostGIS extension required (see below) |
| Redis | **Render Redis** | Session cache & group membership |
| Object storage | **AWS S3 / Cloudflare R2 / MinIO** | Configure via env vars |

---

## 1 — Deploy the API on Render

### 1.1 Connect the repo
1. Go to [render.com](https://render.com) → **New → Blueprint**.
2. Select the `ittai-rovnick/sk` repository and confirm the `render.yaml` file is detected at the repo root.
3. Render will provision:
   - `geo-platform-api` web service (Docker)
   - `geo-meta-db` managed Postgres
   - `geo-features-db` managed Postgres
   - `geo-redis` managed Redis

### 1.2 Enable PostGIS (one-time per database)
Render Postgres supports PostGIS but does not enable it automatically.

In the Render dashboard → **geo-meta-db** → **Connect** → run:
```sql
CREATE EXTENSION IF NOT EXISTS postgis;
```
Repeat for **geo-features-db**.

> **Note:** The Alembic migrations also run `CREATE EXTENSION IF NOT EXISTS postgis;` so this
> step is a safety net in case the migrations run before the extension is available.

### 1.3 Set required secrets in the Render dashboard
After the first deploy, go to **geo-platform-api → Environment** and add:

| Variable | Value |
|----------|-------|
| `API_CORS_ORIGINS` | `["https://<your-app>.vercel.app"]` |
| `STORAGE_ACCESS_KEY` | Your AWS/R2/MinIO access key |
| `STORAGE_SECRET_KEY` | Your AWS/R2/MinIO secret key |
| `STORAGE_ENDPOINT` | S3-compatible endpoint URL, **or leave blank** for native AWS S3 |

`API_SECRET_KEY` is auto-generated by Render on first deploy.

#### Microsoft SSO (optional — only if not using local auth)
| Variable | Value |
|----------|-------|
| `MS_TENANT_ID` | Azure AD tenant ID |
| `MS_CLIENT_ID` | App registration client ID |
| `MS_CLIENT_SECRET` | App registration client secret |

### 1.4 Verify the API
Once deployed, visit:
```
https://geo-platform-api.onrender.com/health
```
Expected response: `{"status":"ok"}`

Swagger UI:
```
https://geo-platform-api.onrender.com/docs
```

## 2 — Deploy the frontend on Vercel

### 2.1 Import the project
1. Go to [vercel.com](https://vercel.com) → **Add New → Project**.
2. Import the `ittai-rovnick/sk` repository.
3. Set **Root Directory** to `geo-platform/web`.
4. Framework preset is auto-detected as **Vite**.

### 2.2 Set environment variables
In Vercel → **Settings → Environment Variables**:

| Variable | Value |
|----------|-------|
| `VITE_API_URL` | `https://geo-platform-api.onrender.com` |

### 2.3 Deploy
Click **Deploy**. Vercel builds with `npm run build` and deploys the `dist/` directory.

All React Router routes are handled by the `vercel.json` rewrite rule (`/* → /index.html`).

### 2.4 Update CORS
After you get the Vercel URL (e.g. `https://my-app.vercel.app`), go back to the Render dashboard and update:
```
API_CORS_ORIGINS = ["https://my-app.vercel.app"]
```
Trigger a manual redeploy of `geo-platform-api` for the change to take effect.

## 3 — CI/CD

The `.github/workflows/ci.yml` workflow runs on every push and pull request:
- **web-build**: runs `npm ci && npm run build` against the Vite frontend.
- **api-check**: installs Python deps and verifies the FastAPI app loads cleanly.

Deployments are triggered automatically:
- **Render** redeploys `geo-platform-api` on every push to the connected branch.
- **Vercel** redeploys the frontend on every push to the connected branch.

## 4 — Local development (unchanged)

```bash
# Start infrastructure
cd geo-platform
docker compose up -d

# Start API (separate terminal)
cd geo-platform/api
venv/Scripts/python run.py        # Windows
# or: python run.py               # macOS/Linux

# Start web (separate terminal)
cd geo-platform/web
npm run dev
```

See `COMMANDS.txt` for full reference.

## 5 — Object storage options

| Provider | `STORAGE_ENDPOINT` | Notes |
|----------|--------------------|-------|
| **AWS S3** | *(leave blank)* | IAM user with S3 permissions |
| **Cloudflare R2** | `https://<account>.r2.cloudflarestorage.com` | S3-compatible, free egress |
| **Backblaze B2** | `https://s3.<region>.backblazeb2.com` | S3-compatible API |
| **MinIO (self-hosted)** | `http://<host>:9000` | Used in local dev via Docker |

For AWS S3, also set the `AWS_DEFAULT_REGION` environment variable (e.g. `us-east-1`).

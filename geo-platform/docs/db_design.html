geo_features Features database :5433 (direct, no pgbouncer)
Partitioned table — HASH(layer_id) → 32 partitions
Physical tables: features_p0 … features_p31. Postgres routes each row automatically.
Every query MUST include layer_id in the WHERE clause for partition pruning. Without it Postgres scans all 32 partitions (full table scan).
features partitioned × 32
All vector geometries. Optimistic locking via version column. Soft-deleted — never hard DELETEd (Argo needs deleted IDs for sync delta).

→has one layer_schema
→has many layer_styles
→has many layer_owners

→has many features (in geo_features DB)

ms_groups (custom)
→has many custom_group_members (users)
→has many custom_group_ms_links (MS Entra IDs)
→referenced by permissions.ms_group_id
permissions (ACL)
→principal: ms_user_id OR ms_group_id
→resource: database_id OR group_layer_id OR layer_id
→role: → roles
→resolved by PostgreSQL function can_user_do() walking up the hierarchy
sync flow
1sync_snapshots — Argo downloads, records timestamp
2features.updated_at > snapshotted_at → delta
3Push: WHERE version = client_version → 0 rows → sync_conflicts
4Non-conflict failures → failed_syncs

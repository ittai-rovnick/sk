Current infrastructure — what actually runs

5 Docker services defined in docker-compose.yml. Always exactly 2 PostgreSQL instances — metadata and features are always separate.

ServiceContainerPortWhat it holdsNotes
postgres_meta geo_meta 5432 All metadata: users, layers, permissions, styles, audit log, sync state — 21 tables Never holds feature geometries. Always accessed via pgbouncer at port 6432.
postgres_features geo_features 5433 All feature geometries + properties. One logical features table, 32 hash partitions on layer_id. This is shard 0. Config supports adding more shards via features_shard_N_url without code changes.
pgbouncer geo_pgbouncer 6432 → 5432 Connection pool for postgres_meta only. 500 client connections → 25 real DB connections. Transaction pool mode. The features DB connects directly (no pgbouncer in front of it).
redis geo_redis 6379 Cache: group memberships, permission results, shard routing table, layer metadata. Redis 7 Alpine. Not a DB — losing it is safe, just slower.
minio geo_minio 9000 (API) / 9001 (console) S3-compatible object store: geo-styles/ (.lyrx files), geo-rasters/ (COG TIFFs), geo-exports/. Only S3 keys stored in PostgreSQL. Presigned URLs generated at request time.

Full API reference

Auth badges: open no token needed   token any authenticated user   superadmin superadmin flag required   permission ACL check on the resource

AUTH

MethodPathDescriptionAuth
POST /auth/login Dev mode only. Body: {"username":"itay"}. Returns token + UserResponse. Auto-creates user as superadmin. open
GET /auth/auto-login Dev mode only. Reads OS %USERNAME% / $USER. Returns token + UserResponse. open
GET /auth/me Returns current user from Bearer token. token

DATABASES — top-level containers that group layers

MethodPathDescriptionAuth
GET /databases List all databases sorted by name. token
POST /databases Create database. Body: name (required), description, default_srid (default 4326), tags[]. Returns 201. superadmin
GET /databases/{database_id} Get single database. token
PUT /databases/{database_id} Update database. All fields optional: name, description, default_srid, tags. superadmin
DELETE /databases/{database_id} Hard delete database. Returns 204. superadmin

LAYERS — vector layer definitions (features stored separately)

MethodPathDescriptionAuth
GET /layers List non-deleted layers. Query: database_id, group_layer_id. Sorted by sort_order then name. token
POST /layers Create layer. Body: database_id*, name*, group_layer_id, description, srid, tags, sort_order. Creator auto-assigned as primary owner. Returns 201. token
GET /layers/{layer_id} Get single layer. token
PUT /layers/{layer_id} Update layer metadata. Optional: name, description, group_layer_id, tags, status (draft/published/archived), sort_order. write perm
DELETE /layers/{layer_id} Soft delete (deleted_at = now()). Returns 204. Never hard-deleted. delete perm
POST /layers/{layer_id}/lock Lock layer — prevents all feature edits. Body: {"reason":"..."} (optional). 409 if already locked. write perm
DELETE /layers/{layer_id}/lock Unlock layer. Only the user who locked it or a superadmin can unlock. lock owner

FEATURES — actual geometries + attribute data (geo_features DB, partitioned by layer_id)

MethodPathDescriptionAuth
GET /layers/{layer_id}/features List features. Query: limit (def 1000), offset, min_lon/min_lat/max_lon/max_lat (bbox — all 4 required), geometry_type. Ordered by id. read perm
GET /layers/{layer_id}/features/{feature_id} Get single feature. read perm
POST /layers/{layer_id}/features Create feature. Body: geom (GeoJSON)*, properties (JSONB). Runs ST_MakeValid. Returns version=1, 201. 409 if locked. write perm
PUT /layers/{layer_id}/features/{feature_id} Update feature with optimistic locking. Body: version* (must match server), geom, properties. Version mismatch → 409, records SyncConflict. Returns incremented version. write perm
DELETE /layers/{layer_id}/features/{feature_id} Soft delete single feature. 409 if layer is locked. Returns 204. delete perm
POST /layers/{layer_id}/features/bulk-delete Soft delete multiple features. Body: {"feature_ids": [1,2,3]}. Returns {"deleted": N}. 409 if locked. delete perm

GROUP-LAYERS — folder tree inside a database

MethodPathDescriptionAuth
GET /group-layers List folders. Query: database_id. Sorted by sort_order then name. token
POST /group-layers Create folder. Body: database_id*, name*, parent_id, description, tags, sort_order. Returns 201. superadmin
GET /group-layers/{group_layer_id} Get single folder. token
PUT /group-layers/{group_layer_id} Update. Optional: name, description, tags, sort_order, parent_id. superadmin
DELETE /group-layers/{group_layer_id} Soft delete. Returns 204. superadmin

PERMISSIONS — ACL system (exactly one principal × exactly one resource × role)

MethodPathDescriptionAuth
GET /roles List all roles (viewer, editor, admin) with capability bitmasks. token
GET /permissions List permissions. Query: layer_id, database_id, or group_layer_id. token
POST /permissions Grant or deny. Body: one of ms_user_id/ms_group_id, one of database_id/group_layer_id/layer_id, role_id, allow (false = explicit deny). Returns 201. Non-superadmin can only grant on layers they have manage_perms for. manage_perms
DELETE /permissions/{permission_id} Revoke permission. Returns 204. manage_perms

SYNC — Argo offline app: snapshot → [work offline] → delta → push

MethodPathDescriptionAuth
POST /sync/snapshot Download all features for requested layers. Body: layer_ids[]*, device_id*, geometry_type. Creates SyncSnapshot with 72h TTL. Returns features_by_layer + snapshot metadata per layer. read perm
GET /sync/delta/{layer_id} Changes since last snapshot. Query: device_id*, geometry_type. Returns {"updated":[...], "deleted":[id,...]}. 410 Gone if snapshot expired. read perm
POST /sync/push Apply offline edits. Body: device_id*, edits[] (each: feature_id, layer_id, operation create/update/delete, version for update/delete, geom, properties). Returns {"succeeded":[], "conflicts":[], "failed":[]}. Conflicts recorded in sync_conflicts. write perm
GET /sync/status/{layer_id} Snapshot health for a device. Query: device_id*. Returns age, expiry, and pending conflict count. read perm

Permission model — ACL with hierarchy cascading, deny wins

Roles (built-in)
viewer — read
editor — read, write, delete, export
admin — read, write, delete, export, manage_style, manage_perms, publish
Custom roles possible via roles table
permissions table structure
Principal: ms_user_id XOR ms_group_id
Resource: database_id XOR group_layer_id XOR layer_id
Role: FK to roles
allow: bool — false = explicit deny
database permission cascades live to all layers
No materialization — always resolved at query time
can_user_do() — PostgreSQL function
Args: ms_object_id, ms_group_ids[], layer_id, operation
1. Walk: layer → group_layer → database
2. Check user + all group entries at each level
3. Any matching deny → return false
4. Any matching allow → return true
5. No match → false (implicit deny)
Superadmin bypasses entirely
Python wrapper in auth/permissions.py

How a feature query flows through the system

Example: Argo requests features in a bounding box for layer X

1. GET /layers/{id}/features?min_lon=…&max_lon=…
→
JWT validated (no network call)
~0ms
2. can_user_do(user, groups[], layer_id, 'read')
→
PostgreSQL function via metadata DB
~2ms (Redis cached)
3. Read layer.shard_id from metadata
→
shard_id = 0 → connect to geo_features :5433
~1ms (Redis cached)
4. Query geo_features, partition features_pN
→
SELECT … WHERE layer_id=X AND ST_Intersects(geom, bbox)
~10–50ms (GIST index)
5. Return GeoJSON FeatureResponse[]
Total: ~15–55ms

How a write request flows through the system

Example: Argo pushes an edit — PUT /layers/{id}/features/{fid}

1. Extract RequestContext from JWT (ms_object_id, ms_group_ids)
~0ms
2. can_user_do(…, 'write') on the layer
→
Deny → 403. No match → 403.
~2ms
3. Check layer.is_locked
→
Locked → 409 Conflict. Stop.
~1ms
4. UPDATE … WHERE id=X AND version=client_version AND deleted_at IS NULL
→
0 rows → version mismatch → 409, write SyncConflict
~5–20ms
5. Write audit_log (async, non-blocking)
~0ms overhead

Argo offline sync flow

Device: POST /sync/snapshot
→
Server creates SyncSnapshot (TTL 72h), returns all features
↓ device works offline — may take hours or days
Device: GET /sync/delta/{layer_id}?device_id=…
→
Returns features updated/deleted since snapshotted_at. 410 if expired.
Device: POST /sync/push
→
Applies create/update/delete with optimistic locking
Server response
→
{"succeeded":[…], "conflicts":[…], "failed":[…]}
Conflicts stored in sync_conflicts for manual resolution

Design decisions — will it work well?

✓ Metadata DB stays fast no matter how big features grow.  Every permission check, layer list, and dashboard load hits only the small metadata DB. Feature shards never affect metadata operations.
✓ Feature queries never slow down as more layers are added.  Every query includes layer_id, so PostgreSQL hits exactly one of 32 partitions. Adding 10,000 more layers doesn't affect query time for existing layers.
✓ Scaling from Tier 1 to Tier 3 requires zero code changes.  Add shards to config, run a migration script to move data. The API shard router never changes.
✓ Argo offline sync is isolated.  Syncing one device's layers doesn't affect other devices or other shards.
✓ Mixed layer sizes handled identically.  A 5-row layer and a 500,000-row layer use the same indexes and queries. No per-layer tuning needed.
✓ Conflict data is never silently lost.  Every optimistic lock mismatch creates a sync_conflicts row. Clients get a structured conflict response. Resolution is explicit and tracked.
! Metadata DB is a single point of failure.  If it goes down, everything stops. Mitigate in production with a hot standby replica. Not needed for local dev.
! Custom group hierarchy not yet inherited in ACL.  MS-linked groups don't walk parent_group_id upward. A permission on a parent group does not yet flow to child groups. Tracked in permission_plan.md.
